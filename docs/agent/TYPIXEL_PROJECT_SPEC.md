# Typixel — 서비스 기획 및 구현 명세

> 상태: 초기 MVP 기획안 / Codex 구현용

## 1. 프로젝트 개요

사용자가 직접 동영상을 선택해 ASCII Art 영상으로 변환하고, 편집 및 미리보기 후 고유 링크로 다른 사람에게 공유하는 웹 서비스다. 회원은 자신이 제작한 영상을 관리할 수 있으며 비회원도 제한적으로 제작할 수 있다.

- 특정 동영상이나 음원을 프로젝트에 내장하지 않는다. 영상은 사용자가 나중에 직접 제공한다.
- 인스타그램 등 외부 플랫폼에서 영상을 자동 수집하거나 다운로드하는 기능은 구현하지 않는다.
- 원본 영상의 오디오를 유지하며 ASCII 영상과 동기화한다.
- 공유 링크를 받은 사람은 로그인 없이 감상할 수 있다.

## 2. 사용자 및 정책

| 기능 | 비회원 | 회원 |
|---|---|---|
| 로컬 변환 및 미리보기 | 가능 | 가능 |
| 공유 영상 생성 | 최근 24시간당 최대 2개 | 한도 미정 |
| 공유 영상 보관 | 생성 완료 후 24시간 | 보관 기간 미정 |
| 내 영상 조회 및 삭제 | 동일 게스트 세션에서 가능 | 계정 기반으로 가능 |
| 다른 기기에서 관리 | 불가 | 가능 |
| 공유 링크 감상 | 가능 | 가능 |

비회원 2개 제한은 최근 24시간 내 공유 생성 기준으로 제안한다. 단순 로컬 미리보기는 차감하지 않으며, 게시 후 삭제해도 사용량은 복구하지 않는다. 회원 한도 및 보관 정책은 확정 전까지 설정값으로 분리하고 운영 배포 전 결정한다. 무제한 저장을 기본값으로 가정하지 않는다.

## 3. 사용자 흐름

1. A가 메인 페이지(`/`)에 접속한다. 로그인 여부와 관계없이 즉시 동영상 파일을 선택하거나 드래그 앤 드롭할 수 있다.
2. 파일을 선택하면 임시 영상이 생성되고, 메인 페이지의 편집 화면에서 ASCII 변환 설정과 오디오를 확인할 수 있다.
3. A가 `New video`를 누르면 빈 편집 화면이 열린다. 다른 파일을 넣거나 사이드바의 기존 임시 영상 항목을 눌러 작업을 이어갈 수 있다.
4. 현재 편집 중인 영상에서 `Export`를 누르면 서버가 인증 및 제작 한도를 확인하고 업로드 권한을 발급한다.
5. 원본 파일을 R2에 업로드하고 검증한 뒤, PostgreSQL에 저장 키, 변환 설정, 출력 볼륨, 소유자 및 공유 ID를 저장한다.
6. Export가 완료되면 영상이 사이드바의 `My recent videos`에 표시된다. A는 공유 링크(`/watch/[shareId]`)를 복사하여 B에게 전달한다.
7. B는 로그인 없이 링크에 접근하고 재생 버튼을 눌러 영상과 음악을 감상한다.
8. A는 내 영상 페이지에서 목록, 만료 시간, 링크 복사, 삭제 기능을 이용한다.

동영상 선택, 편집, 미리보기, 공유 링크 생성은 모두 메인 페이지(`/`)에서 이루어지며 별도의 편집 페이지로 이동하지 않는다.

## 4. 페이지 구성

| 경로 | 역할 |
|---|---|
| `/` | 동영상 선택 및 업로드, ASCII 변환, 편집, 미리보기, 공유 링크 생성 |
| `/watch/[shareId]` | 몰입형 ASCII 영상 감상 |
| `/my-videos` | 소유 영상 목록 및 관리 |

Google 로그인은 스튜디오 헤더에서 모달로 시작한다. 최초 Google OAuth 로그인 시 회원 계정을 생성한다.

### 4.1 메인 페이지 (`/`)

메인 페이지는 서비스의 핵심 기능을 하나의 페이지에서 제공한다. 별도의 `/editor` 경로를 사용하지 않는다.

**사이드바**

- **`New video`**는 더하기 아이콘이 있는 버튼이다. 누르면 기존 임시 영상을 목록에 남겨 둔 채 기본값으로 빈 편집 화면을 연다. 파일을 넣을 때 임시 영상 항목을 만든다.
- **임시 영상**에는 현재 브라우저 탭에서 편집 중인 영상이 표시된다. 항목을 선택하면 해당 원본 파일과 마지막 편집 설정을 복원한다. 파일이나 편집 설정은 Export를 시작하기 전까지 서버로 전송하지 않는다.
- **`My recent videos`**에는 현재 사용자 또는 게스트가 Export를 완료한 영상이 최신순으로 표시된다. 항목에서 공유 링크를 열거나 복사할 수 있다.

**초기 상태**

- 페이지 접속 즉시 동영상 파일 선택 가능
- 드래그 앤 드롭 지원
- 로그인하지 않아도 영상 선택 및 변환 가능

**편집 상태**

- 파일 선택 시 페이지 이동 없이 편집 UI 활성화
- 실시간 ASCII 영상 미리보기
- ASCII 변환 옵션 조정
- 원본 오디오 재생
- 영상 재생, 정지 및 탐색
- `New video`로 새 작업을 시작하고 사이드바에서 기존 임시 영상으로 전환 가능

**Export 및 공유 상태**

- `Export` 버튼으로 선택한 원본 파일과 버튼을 누른 시점의 편집 설정을 저장
- 업로드 진행 상태 표시
- 생성된 공유 링크 표시 및 복사
- 업로드 실패 및 제작 한도 초과 안내
- Export 완료 시 `My recent videos` 갱신, 실패 시 임시 영상과 편집 설정 유지
- 공유 링크 생성 이후에도 메인 페이지 유지

### 4.2 공통 UI 정책

UI는 검은 배경, 고정폭 흰색 문자, 간결한 재생 컨트롤을 기본으로 한다. 모바일 반응형을 지원하며 감상 화면에서는 불필요한 편집 UI를 노출하지 않는다. 만료, 삭제, 존재하지 않는 링크와 업로드 실패 상황을 명확히 안내한다.

## 5. ASCII 변환

### 기본 알고리즘

- HTMLVideoElement를 단일 영상 및 오디오 재생 기준으로 사용한다.
- Canvas 2D의 `drawImage()`로 프레임을 축소하고 `getImageData()`로 RGBA 데이터를 읽는다.
- 밝기: `0.299 * R + 0.587 * G + 0.114 * B`.
- 밝기를 문자 배열 ` .:-=+*#%@`에 매핑한다. 검은 배경에서는 밝을수록 밀도가 높은 문자를 사용한다.
- 실제 고정폭 폰트의 문자 폭/줄 높이에 따라 출력 행 수를 보정한다.
- `requestVideoFrameCallback()`을 우선 사용하고 미지원 브라우저에서는 `requestAnimationFrame()`으로 대체한다.
- React state와 Zustand Store를 매 프레임 변경하지 않고 ref 및 Canvas 렌더러를 활용한다. 정지, 탐색, 종료, 언마운트 시 렌더링 루프와 Object URL을 정리한다.
- 소리 자동 재생 제한을 고려해 명시적 재생 버튼을 제공한다. 영상에 포함된 음악을 유지하고 별도 오디오 타이머를 사용하지 않는다.

### 편집 옵션

문자 해상도, 문자 집합, 밝기, 대비, 감마, 임계값, 흑백/컬러, 배경색, 문자색, 볼륨, 반복 재생을 지원한다. 설정값은 서버에서도 검증한다. 재생 시 사용자의 볼륨 변경은 공유 설정을 자동 변경하지 않는다.

Export에는 오른쪽 편집 패널의 출력 볼륨(0~100%)을 저장한다. 중앙 재생 컨트롤의 미리보기 볼륨은 편집 화면에서 듣는 소리에만 적용한다.

### 저장 방식

임시 영상은 클라이언트에서 관리한다. Export 시 원본 영상은 비공개 R2 버킷에 저장하고, PostgreSQL에는 저장 키와 변환 설정 등 공유에 필요한 정보를 저장한다. 공유 링크를 열면 시청자 브라우저에서 원본을 ASCII로 렌더링한다. 이후 ASCII 결과 영상을 Canvas captureStream/MediaRecorder 또는 별도 인코딩 방식으로 생성하여 저장하는 방식으로 확장할 수 있다. 결과 영상 방식은 오디오 합성, 코덱 호환성, 인코딩 시간을 별도로 검증해야 한다.

## 6. 기술 스택 및 아키텍처

| 영역 | 기술 |
|---|---|
| 웹 | Next.js App Router, TypeScript |
| 스타일 | Tailwind CSS |
| 편집 상태 | Zustand |
| 인증 | Better Auth (Google OAuth, 익명 인증 및 계정 연결 검토) |
| DB/ORM | PostgreSQL / Prisma |
| 파일 저장 | Cloudflare R2 비공개 버킷 |
| 변환 | Canvas API, 필요 시 Web Worker / OffscreenCanvas |
| 요청 제한 | Redis (Upstash 등), 필요 시 Turnstile |
| 배포 | Vercel |
| 만료 처리 | 인증된 Cron Job 및 스토리지 정리 작업 |

Next.js Route Handler가 인증, 메타데이터, 권한, 서명 URL을 관리한다. 대용량 영상은 Next.js 서버를 경유하지 않고 서명된 업로드 URL로 R2에 직접 전송한다. PostgreSQL에는 영상 바이너리가 아닌 저장 키, 변환 설정, 소유자, 만료일 등을 저장한다.

### 6.1 클라이언트 상태 관리

사이드바와 편집 화면이 공유하는 임시 영상 상태는 Zustand를 사용한다. 첫 구현에서는 현재 브라우저 탭의 메모리에 유지하며, 새로고침하거나 탭을 닫으면 임시 영상 상태가 초기화된다. 새로고침 후 복원이 필요해지면 IndexedDB를 별도 단계에서 검토한다.

`stores/editorStore.ts`의 주요 관리 대상은 다음과 같다.

- 임시 영상 목록과 현재 선택한 임시 영상의 ID. 빈 편집 화면에서는 선택한 ID가 없다.
- 임시 영상별 원본 `File`, 메타데이터, ASCII 변환 설정 및 출력 볼륨
- 재생 및 일시정지 상태
- 볼륨 및 반복 재생 설정
- 업로드 진행 상태
- 생성된 공유 링크
- 빈 편집 화면 열기 및 임시 영상 선택

각 컴포넌트는 필요한 상태만 selector를 통해 구독한다.

매 프레임 생성되는 ASCII 문자열, 픽셀 데이터 및 고빈도 렌더링 데이터는 Zustand에 저장하지 않는다. 이러한 데이터는 ref와 Canvas 렌더러를 통해 처리하여 불필요한 React 리렌더링을 방지한다.

컴포넌트 내부에서만 사용하는 단순 UI 상태는 React의 로컬 상태를 사용할 수 있다.

## 7. 인증과 게스트 식별

### 7.1 회원 인증

- 회원 인증은 Google OAuth 로그인만 지원한다.
- 스튜디오 헤더 오른쪽의 `Sign in` 버튼으로 로그인 모달을 열고, `Continue with Google`을 선택하면 Google 인증 화면으로 이동한다.
- 인증에 성공하면 메인 페이지로 돌아오고, 취소하거나 실패하면 로그인 모달에 재시도 안내를 표시한다.
- 로그인한 사용자의 프로필 버튼을 누르면 이름과 `Sign out`이 표시된다. 로그아웃하면 현재 세션을 종료하고 편집 상태를 유지한 채 헤더에 `Sign in`을 표시한다.
- 이메일 및 비밀번호 기반 자체 회원가입과 로그인은 구현하지 않는다.
- 최초 Google 로그인 시 회원 계정을 자동으로 생성한다.
- 기존 회원은 연결된 Google 계정으로 로그인한다.
- 비밀번호 저장, 변경, 재설정 기능은 구현하지 않는다.
- Google OAuth 권한 범위는 기본 프로필 및 이메일 확인에 필요한 범위로 제한한다.

### 7.2 비회원 식별

비회원 식별에 사람 단위의 완벽한 표준은 없다. 익명 세션과 HTTP 쿠키를 이용한다.

- Better Auth의 익명 인증을 우선 검토하고, 적용 시 익명 계정과 일반 계정을 하나의 User 모델로 관리한다.
- 직접 구현한다면 서버가 암호학적으로 안전한 랜덤 토큰(UUID v4 또는 32바이트 랜덤 값)을 발급하고 서버 DB에는 토큰 해시를 저장한다.
- 쿠키는 HttpOnly, Secure(운영 HTTPS), SameSite=Lax, Path=/로 설정한다. 게스트 세션 유지 기간은 영상 보관 기간과 별개로 관리한다(예: 30일, 제안값).
- 서버가 세션과 소유권을 검증한다. 클라이언트가 전달한 userId, guestId, 사용량 수치를 신뢰하지 않는다.
- 쿠키 삭제, 다른 브라우저, 시크릿 모드로 제한을 우회할 수 있다. IP 기반 요청 제한과 CAPTCHA를 보조적으로 사용한다. IP만으로 개인을 식별하지 않는다.
- Google OAuth 로그인 시 현재 게스트 세션의 소유 영상과 사용량을 안전하게 계정에 연결하는 기능을 제공한다. 기존 계정 로그인 및 신규 계정 생성 모두 검증하고 중복 이전을 방지한다. 이전만으로 기존 영상 만료일을 자동 연장하지 않는다.

## 8. 데이터 모델 (논리 설계)

Better Auth 기반의 Google OAuth 인증 및 비회원 익명 인증을 전제로 한다. 인증 관련 테이블은 Better Auth에서 제공하는 Prisma 스키마를 기반으로 구성한다.

| 모델 | 역할 | 주요 필드 |
|---|---|---|
| User | 회원 및 비회원 사용자 정보 관리 | id, email, emailVerified, name, image, isAnonymous, createdAt, updatedAt |
| Account | Google OAuth 계정과 서비스 사용자 연결 및 인증 정보 관리 | id, userId, providerId, accountId, accessToken, refreshToken, idToken, scope, createdAt, updatedAt |
| Session | 사용자 로그인 상태 및 세션 유효기간 관리 | id, userId, token, expiresAt, ipAddress, userAgent, createdAt, updatedAt |
| Verification | 인증 과정에서 필요한 임시 검증 정보 관리 | id, identifier, value, expiresAt, createdAt, updatedAt |
| Video | 공유 영상의 메타데이터, 변환 설정, 소유권 및 만료 정보 관리 | id, shareId, ownerId, title, storageKey, settings, status, sizeBytes, duration, createdAt, expiresAt, deletedAt |
| CreationLog | 영상 생성 이력 및 사용자별 제작 한도 관리 | id, ownerId, videoId, status, createdAt, reservationExpiresAt |

`User`, `Account`, `Session`, `Verification`은 Better Auth의 인증 관련 모델이며, `Video`, `CreationLog`는 Typixel의 서비스 기능을 위한 자체 모델이다.

실제 인증 필드는 Better Auth에서 생성하는 스키마를 기준으로 구성하며, 위 표는 주요 필드만 명시한 논리 설계다.

Video 상태: PENDING_UPLOAD → READY / FAILED → DELETING / EXPIRED. 각 공유 ID는 예측하기 어려운 충분한 랜덤 값을 사용하고 내부 DB ID와 분리한다. ownerId, expiresAt, status, CreationLog(ownerId, createdAt)에 인덱스를 설정한다.

사용량 검사와 업로드 예약을 원자적으로 처리하여 동시 요청으로 2개 한도를 초과하지 못하게 한다. 업로드 실패 또는 예약 만료 시 예약을 회수하며, 성공한 공유 생성 이력은 영상 삭제와 독립적으로 제한 기간 동안 보관한다. 재시도에는 idempotency key를 적용한다.

## 9. API 설계

| Method | Endpoint | 역할 |
|---|---|---|
| \* | `/api/auth/[...all]` | 인증 라이브러리 핸들러 |
| POST | `/api/uploads` | 인증, 한도 예약, 업로드 URL 발급 |
| POST | `/api/videos` | 업로드 검증, READY 처리, 공유 ID 반환 |
| GET | `/api/videos` | 현재 소유자의 영상 목록 |
| GET | `/api/watch/[shareId]` | 공개 감상용 설정 및 단기 재생 URL |
| PATCH | `/api/videos/[id]` | 소유자 설정 수정 |
| DELETE | `/api/videos/[id]` | 소유자 영상 삭제 |
| POST | `/api/internal/cleanup` | 인증된 스케줄러의 만료 정리 |

응답 상태 예시: 400 입력 오류, 401 인증 필요, 403 권한 부족, 404 없는 링크, 410 만료 링크(삭제 후 404 가능), 413 용량 초과, 429 제한 초과. 업로드 완료 시 서버가 객체의 존재 및 크기를 확인하고 허용 형식과 실제 미디어 정보를 검증한다. 파일 크기 및 길이 상한은 운영 전 결정한다.

## 10. 만료 및 삭제

- 게스트 영상은 공유 생성 완료 후 24시간으로 expiresAt을 서버에서 지정한다.
- 만료 시점부터 조회/재생 URL 발급을 차단한다. 서명 URL 유효기간은 영상의 남은 보관 시간보다 길지 않게 설정한다.
- 주기적 정리 작업은 원본 영상 및 고아 업로드를 R2에서 삭제하고 해당 메타데이터를 정리한다. 실패 시 재시도할 수 있도록 한다.
- 물리 삭제는 스케줄 실행 주기만큼 지연될 수 있다. 이미 내려받은 파일까지 회수할 수는 없다.
- 생성 한도 이력은 영상 삭제와 별도로 최소 필요 기간만 보관한다.

## 11. 보안 및 저작권

- 특정 저작권 콘텐츠를 소스 저장소, 샘플, 시드 데이터에 포함하지 않는다.
- 업로드 시 영상과 음원에 대한 이용 권한 확인을 받는다. 범용 플랫폼 구조만으로 저작권 책임이 면제되지는 않는다.
- 공개 검색 및 추천 기능은 MVP에서 제외한다.
- 공유 링크는 링크를 가진 누구나 접근 가능한 비공개 목록형(unlisted)으로 정의한다. 비밀번호 보호는 확장 기능이다.
- R2는 공개 버킷으로 운영하지 않는다. 서명 URL, 필요한 CORS 정책, HTTPS를 적용한다.
- 파일 이름과 MIME만 신뢰하지 않고 검증한다. 용량, 길이, 업로드 빈도 제한을 적용한다.
- 변경 API는 인증, 소유권, Origin/CSRF 검증을 적용한다. 비밀 키는 서버 환경 변수에만 둔다.
- 공유 페이지는 검색 엔진 색인 제외 설정을 적용한다. 이것이 접근 통제 수단은 아니다.

## 14. Codex 구현 지시사항

1. 기존 저장소를 먼저 검사하고 기존 코드를 불필요하게 덮어쓰지 않는다.
2. 이 문서의 MVP 순서대로 구현하며 각 단계에서 타입 검사, 빌드 및 관련 테스트를 진행한다.
3. 사용자가 영상 파일을 나중에 직접 제공할 예정이므로 특정 영상을 생성하거나 다운로드하지 않는다. 파일이 없는 상태에서도 메인 화면과 업로드 UI는 정상 작동해야 한다.
4. 실제 환경 변수 및 인증 비밀값을 임의로 생성해 커밋하지 않는다. `.env.example`과 README에 필요한 설정을 문서화한다.
5. 미확정 정책은 설정값 및 문서로 분리하고 확인 없이 회원 무제한 저장이나 추가 유료 인프라를 도입하지 않는다.
6. 실제 영상, 인증 제공자, DB/R2 자격 증명이 없는 테스트는 수행한 것처럼 보고하지 않는다.
7. 회원 인증은 Google OAuth만 구현하며 자체 회원가입, 비밀번호 인증 및 다른 소셜 로그인은 구현하지 않는다.
8. MVP 범위에 포함되지 않은 기능은 임의로 추가하지 않는다.
9. 편집 관련 공유 상태는 Zustand로 관리하며 별도의 전역 상태 관리 라이브러리를 도입하지 않는다. 매 프레임 발생하는 데이터는 Store에 저장하지 않는다.
10. 인증 관련 데이터 모델은 Better Auth에서 제공하는 스키마를 기반으로 구성하고 필수 인증 필드를 임의로 제거하지 않는다.

## 15. 미확정 사항

- 최종 UI 디자인
- 회원 제작 한도 및 영상 보관 기간
- 파일 크기, 길이, 해상도 제한과 지원 코덱
- 인프라 예산 및 Cron 주기
- 변환 결과 인코딩 방식
- 별도 음악 업로드 기능(기본 MVP는 영상에 포함된 오디오 유지)

비회원 2개 제한을 최근 24시간 기준으로 해석한 점, 로컬 미리보기는 제한에서 제외한 점, Better Auth와 원본+설정 저장 방식을 우선 채택한 점은 초기 설계 제안이며 변경 가능하다.
